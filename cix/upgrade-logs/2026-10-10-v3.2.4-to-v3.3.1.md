v3.3.0 在 2026-10-06 发布（正好是切到 v3.2.4 那天），v3.3.1 在 10-08。ML 层重写，是这次移植的主要工作。

## 上游变化（与 fork 相关的部分）

- ML：`pipeline.py`（严格校验请求）、session/graph 两层协议、`ShapePolicy`、只针对 ORT 的 `prepare.py`；`requires-python >= 3.12`；新 git 依赖 `immich-model`（immich-app/ml-models）
- ML：OCR 不再写死 ORT；某个格式没有模型文件时抛 `FileNotFoundError`，`main.py` 退回 ONNX
- ML：`MACHINE_LEARNING_MODEL_REVISION=v2` 提供重新导出的优化模型（opt-in，上游打算以后设为默认），缓存路径多一层 `v2/`
- ML：PP-OCRv6（tiny/small/medium）；open_clip 的 `resize_mode: squash` 上游自己支持了
- server：ESM（import 带 `.js`）+ import 排序 lint；`isVideoVertical` 改为 `(h>w) XOR rotated`，新增 `isFrameVertical()`
- server↔ML 的 `/predict` 协议没变

## 演练（数据库副本 + overlay 媒体库，server :2284 只监听 127.0.0.1，ML :3013）

- 启动：4 个迁移成功、无 schema drift、挂载检查通过、插件加载、`tonemapx` 回退日志
- API 冒烟：统计、人物、系统配置、中英文智能搜索（经 NPU）、缩略图、地图（国家名已是 "China" 等新写法）正常；`refresh-faces` 结果与已有人脸完全一致
- `refresh-metadata`：除国家名外与生产逐字段一致
- 视频（V4L2M2M 硬解）：8 个 HDR/旋转 HEVC + 1 个竖存再旋转 90° 的 4K HLG。凡是生产文件由 v3.2.4 转出的（6 个），输出**逐比特一致**；其余 3 个的生产文件是 v2 时代的，不可比
- 软解路径（临时关 `accelDecode`）：竖存再旋转的视频输出 1280x720，吃到了上游的 `isFrameVertical` 修复
- **发现 fork 的老 bug**：zscale 回退里 `tonemap` 的峰值取自帧元数据，一批 Android HLG 视频的元数据是垃圾（0.5 nit）→ 软解画面全是色块（生产里 16 个视频缩略图是坏的）；另外硬解时 PQ 实际按 peak 10 映射、软解按 100（更暗）。修复 `65eb2194c`：一律 `peak=10`，硬解输出逐比特不变，软解与硬解一致（39–41 dB）。详见 [ffmpeg-vpu.md](../findings/ffmpeg-vpu.md#peak-必须写死2026-10-10-发现)
- 演练工具：`start.sh` 加了 `IMMICH_HOST=127.0.0.1`（数据库副本里是真实用户和照片，演练实例只该本机访问）
