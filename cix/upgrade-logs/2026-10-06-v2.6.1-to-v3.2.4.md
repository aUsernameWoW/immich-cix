# 2026-10-06：v2.6.1 → v3.2.4，以及 Chinese-CLIP

一天之内完成：调查 → 修生产隐患 → 移植补丁 → 演练 → 切换 → 换智能搜索模型。

## 起点

- fork 停在 v2.6.1+23（2026-03-23 的 merge），落后上游 1568 个提交；上游已到 v3.3.0-rc.2，最新稳定版 v3.2.4
- 补丁规模很小：16 个文件，主要是 V4L2M2M（server/web/OpenAPI）和 CIX NPU（ML）

## 调查结论

三路并行调查（server 移植、ML 移植、v3 破坏性变更）后的判断：

- **目标选 v3.2.4**：v3.3.0-rc.0 起 ML 层重写且要求 Python ≥ 3.12；v3.2.4 仍是旧架构 + 3.11，补丁几乎能直接搬
- server↔ML 的 `/predict` 协议从 v2.6 到 v3.3 没变，server 可以独立升级
- 对 v3.2.4 做 `merge-tree`：只有生成文件 `fetch-client.ts` 冲突；但 `media.ts` 的"干净合并"有语义问题（HLS 下的参数拼接）
